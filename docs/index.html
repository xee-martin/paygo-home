PAYGO · API REFERENCE

PayGo 开发文档

使用 Browser SDK 创建订单和收银台；以签名验证的 Webhook 作为最终支付确认。

SECRET 仅能保存在商户服务端。 绝不能放入浏览器、移动端或公开代码仓库。

快速开始

在商户后台配置 PID、SECRET、Webhook、收款方式与 Browser SDK Origin 白名单。由商户服务端按真实订单生成一次性签名参数，再由浏览器调用 PayGo.mount()。

  1. 服务端生成订单参数
  2. HMAC-SHA256 签名
  3. 页面调用 PayGo.mount()
  4. 收银台与状态更新
  5. Webhook 最终确认

签名规则

按固定字典顺序串接 amount、merchant_order_no、name、nonce、pid、return_url、timestamp、type。每个值使用 RFC 3986 percent-encoding，计算 HMAC-SHA256(canonical, SECRET)，输出小写 64 位十六进制。

$fields = ['pid' => getenv('PAYGO_PID'), 'merchant_order_no' => $order->number, 'amount' => number_format($order->amount, 2, '.', ''), 'name' => $order->name, 'type' => 'wechat', 'return_url' => 'https://merchant.example/pay/result', 'timestamp' => (string) time(), 'nonce' => bin2hex(random_bytes(16))];
ksort($fields, SORT_STRING);
$canonical = implode('&', array_map(static fn (string $key): string => $key . '=' . rawurlencode((string) $fields[$key]), array_keys($fields)));
$fields['sign'] = hash_hmac('sha256', $canonical, getenv('PAYGO_SECRET'));

timestamp 有效窗口为 ±5 分钟；同一 pid + nonce 只能使用一次。任何已签名字段被改动都会使签名失效。

Browser SDK

SDK 从后台前端域名加载，支付请求发送到 API 域名。SDK 不接受也不会暴露 SECRET、token 或 checkout URL。

<div id="paygo-checkout"></div>
<script src="https://app.paygo2.uk/sdk/paygo.js"></script>
<script>
PayGo.mount('#paygo-checkout', {
  pid: '10001', merchant_order_no: 'ORDER-10001',
  amount: '99.00', name: 'Order payment', type: 'wechat',
  timestamp: '1790770000', nonce: 'xxxxxxxxxxxxxxxx',
  sign: 'SERVER_GENERATED_HMAC_SHA256', return_url: 'https://merchant.example/pay/result',
  lang: 'en', onSuccess(data) { console.log('paid', data); }
});
</script>
示例值不可直接用于生产。 每笔订单的 pid、订单字段、timestamp、nonce 与 sign 都必须由服务端动态输出。

Browser SDK 回调

以下函数仅用于浏览器界面，不属于下单 JSON 参数；支付履约以服务端验签后的 Webhook 为准。

参数说明
onSuccess(data)支付成功时调用，data 为当前订单快照
onExpired(data)订单过期时调用，data 为当前订单快照
onCancelled(data)订单取消时调用，data 为当前订单快照
onError(error)请求异常时接收 Error（message 为说明）；订单状态为 error 时接收订单快照

cURL 下单联调

无需登录文档平台。需要 Bash、Python 3 和支持 --fail-with-body 的 cURL（7.76.0 或更新版本）；在本机交互式终端运行。先填写自己的 PID、白名单 Origin（无路径和末尾斜线）与支付返回地址。

export PAYGO_PID='YOUR_MERCHANT_PID'
export PAYGO_ORIGIN='https://your-merchant.example'
export PAYGO_RETURN_URL='https://your-merchant.example/pay/result'

复制并执行下面完整脚本，或下载脚本后运行 bash create-order.sh。SECRET 在终端隐藏输入，仅在本机用于签名，不写入请求正文。金额和支付方式在 fields 中修改；默认 1.00 元、支付宝，需已启用对应通道。每次执行会创建新的订单号、时间戳和 nonce。

下载完整下单脚本

#!/usr/bin/env bash
# Requires Bash, Python 3, and cURL. Run locally; never paste SECRET into this file.
set -euo pipefail
: "${PAYGO_PID:?Set PAYGO_PID to your merchant PID}"
: "${PAYGO_ORIGIN:?Set PAYGO_ORIGIN to your allowlisted page Origin}"
: "${PAYGO_RETURN_URL:?Set PAYGO_RETURN_URL to your payment return URL}"
export PAYGO_PID PAYGO_ORIGIN PAYGO_RETURN_URL

payload="$(python3 - <<'PY'
import getpass
import hashlib
import hmac
import json
import os
import secrets
import time
from urllib.parse import quote, urlsplit

origin = urlsplit(os.environ['PAYGO_ORIGIN'])
return_url = urlsplit(os.environ['PAYGO_RETURN_URL'])
if (origin.scheme not in ('http', 'https') or not origin.netloc
        or origin.path or origin.query or origin.fragment
        or origin.username or origin.password):
    raise SystemExit('PAYGO_ORIGIN must be an http(s) Origin without a path or credentials')
if (return_url.scheme not in ('http', 'https') or not return_url.netloc
        or return_url.username or return_url.password):
    raise SystemExit('PAYGO_RETURN_URL must be an http(s) URL without credentials')
secret = getpass.getpass('PayGo SECRET (hidden, local signing only): ')
if not secret:
    raise SystemExit('SECRET must not be empty')
fields = {
    'pid': os.environ['PAYGO_PID'],
    'merchant_order_no': 'CURL-' + str(int(time.time())) + '-' + secrets.token_hex(8),
    'amount': '1.00',
    'name': 'cURL integration test',
    'type': 'alipay',
    'return_url': os.environ['PAYGO_RETURN_URL'],
    'timestamp': str(int(time.time())),
    'nonce': secrets.token_hex(16),
}
canonical = '&'.join(key + '=' + quote(fields[key], safe='-._~') for key in sorted(fields))
fields['sign'] = hmac.new(secret.encode(), canonical.encode(), hashlib.sha256).hexdigest()
print(json.dumps(fields, ensure_ascii=False))
PY
)"

printf '%s' "$payload" | curl --silent --show-error --fail-with-body \
  --connect-timeout 10 --max-time 30 \
  --request POST 'https://api.paygo2.uk/api/v1/paygo/checkout/sessions' \
  --header "Origin: $PAYGO_ORIGIN" \
  --header 'Content-Type: application/json' \
  --data-binary @-
printf '\n'

脚本会向真实接口创建订单，请按需运行。检查 JSON 中 code 是否为 0，再查看 data 的订单状态和收银台字段；创建成功不代表支付成功。超时也可能已经创建订单，先在商户后台确认，不要盲目重复下单。支付确认以验签后的 Webhook 为准。

请求返回参数

下单接口返回 JSON，code 为 0 表示成功，订单信息位于 data。下表仅列出商户对接常用字段，SDK 内部通信和重复展示字段已省略；实际响应可能包含其他字段。

参数类型说明
codenumber业务状态码；0 为成功，非 0 时根据 message 和错误码处理，不能只判断 HTTP 200
messagestring结果说明；成功通常为 success
dataobject成功时为订单对象；业务失败时可能为空数组，先检查 code 再读取订单字段
data.trade_idstringPayGo 平台订单号
data.merchant_order_nostring请求中提交的商户订单号，用于关联业务订单
data.statusstring订单状态：pending 待支付、paid 已支付、expired 已过期、cancelled 已取消；创建成功不代表支付成功
data.amountstring原始订单金额字符串，与 currency 配套使用
data.currencystring订单币种，如 CNY
data.actual_amountstring买家实际应付数量字符串；扫码支付为人民币金额，链上支付为对应资产数量。展示或支付时以此为准
data.token / data.networkstring支付资产与网络，结合 actual_amount 识别支付单位和通道
data.checkout_urlstring本次订单的收银台地址，可用于跳转支付；Browser SDK 会自动展示收银台
data.qr_codeobject仅待支付时返回。format=svg 时 data 为 Base64 编码 SVG；format=image 时 url 为图片地址，mime 为图片类型
data.receive_addressstring链上收款地址，仅待支付时提供；微信或支付宝扫码支付请使用 qr_code
data.expires_atstring订单过期时间，ISO 8601 格式，包含时区

签名计算

下单签名完整示例

以下使用虚构 SECRET 和固定时间戳，只用于核对算法。真实请求必须使用当前时间和新的 nonce。HMAC-SHA256 是消息认证码；SECRET 作为密钥，不拼接到原文末尾。

SECRET = paygo_demo_secret

canonical =
amount=99.00&merchant_order_no=ORDER-10001&name=Order%20payment&nonce=0123456789abcdef0123456789abcdef&pid=10001&return_url=https%3A%2F%2Fmerchant.example%2Fpay%2Fresult&timestamp=1792108800&type=alipay

sign = HMAC-SHA256(canonical, SECRET)

服务端最终确认

PayGo 以 application/json 推送 paid 事件，并携带 X-PayGo-Event-Id、X-PayGo-Timestamp、X-PayGo-Nonce 和 X-PayGo-Signature 标头。浏览器回调只能更新界面，必须由服务端 Webhook 验签后履约。

$rawBody = (string) file_get_contents('php://input');
$timestamp = (string) ($_SERVER['HTTP_X_PAYGO_TIMESTAMP'] ?? '');
$nonce = (string) ($_SERVER['HTTP_X_PAYGO_NONCE'] ?? '');
$signature = (string) ($_SERVER['HTTP_X_PAYGO_SIGNATURE'] ?? '');
$expected = hash_hmac('sha256', $timestamp . "\n" . $nonce . "\n" . hash('sha256', $rawBody), getenv('PAYGO_SECRET'));
if (!hash_equals($expected, strtolower($signature))) { http_response_code(401); exit('Invalid signature'); }
// Fulfil idempotently by merchant_order_no, then return plain-text success.

保留原始请求 body；以 merchant_order_no 实现幂等履约；验签成功后返回纯文本 success。

支付方式

wechat

微信收款码支付；需要已验证收款码。

alipay

支付宝收款码支付；需要已验证且启用的收款码。

usdt.tron

TRON 网络上的 USDT；需要当前网络的启用钱包。

trx.tron

TRON 网络上的 TRX；需要当前网络的启用钱包。

实际可用性取决于商户启用状态、有效订阅权益以及收款码或钱包配置。

常见错误

Code含义处理建议
40101商户验证无效检查 PID、签名字段与 SECRET。
40102 / 40103 / 40104时间戳、nonce 或签名无效校准服务端时间，使用新 nonce，并按固定顺序签名。
40302Origin 不在白名单在商户后台配置当前页面的精确 Origin。
40901 / 40902nonce 已用或同订单号参数不同每笔订单生成 nonce；同一订单号保持参数一致。
42202金额格式无效或低于 ¥1.00以最多两位小数的字符串传入，且不得低于 1.00。
